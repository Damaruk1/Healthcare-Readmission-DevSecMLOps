# Model Card: 30-Day Readmission Risk Model

## Model Details

- **Model type:** Random Forest Classifier (scikit-learn), selected automatically
  from a 6-model comparison based on held-out test ROC AUC.
- **Version:** 1.0.0
- **Trained:** see `models/model_metadata.json` → `trained_at` for the exact
  timestamp of the artifact currently deployed.
- **Framework:** scikit-learn 1.9, tuned with Optuna, tracked with MLflow.
- **Input:** 25 clinical/demographic features per patient (see
  `docs/API_DOCUMENTATION.md` for the full schema).
- **Output:** binary prediction (readmitted within 30 days: yes/no) + calibrated
  probability + a 4-level risk bucket (Low / Moderate / High / Very High).

## Intended Use

Educational / portfolio demonstration of a full DevSecMLOps lifecycle for a
binary clinical-risk classification problem. **Not intended for, and not
validated for, real clinical use.** See `docs/HEALTHCARE_DISCLAIMER.md`.

## Training Data

- 100% synthetically generated (`src/data_generation/generate_data.py`),
  5,000+ rows, 27 columns, ~22% positive class rate (imbalanced by design).
- Features are correlated with the synthetic target via an explicit,
  clinically-motivated weighted risk score (see `_compute_readmission_target`
  in the generator) — higher glucose/HbA1c, more chronic conditions, more
  prior admissions/ER visits, longer stays, more medications, older age, and
  no scheduled follow-up all increase readmission probability, matching
  patterns reported in real readmission-risk literature.
- Missingness, limited outliers, and duplicate rows are injected
  intentionally to exercise the validation/preprocessing pipeline.

## Model Comparison (5-fold CV + Optuna-tuned, test-set ROC AUC)

| Model | CV ROC AUC | Test ROC AUC |
|---|---|---|
| Logistic Regression | 0.781 | 0.781 |
| **Random Forest (selected)** | **0.938** | **0.791** |
| Gradient Boosting | 0.934 | 0.779 |
| XGBoost | 0.944 | 0.777 |
| LightGBM | 0.940 | 0.751 |
| CatBoost | 0.940 | 0.771 |

*(Exact values will vary slightly run-to-run and are logged per-run in
MLflow; the table above reflects a representative full run at
`optuna_trials=20`, `cv_folds=5`.)*

Note the CV/test gap across the tree ensembles (~0.93 CV vs ~0.78 test) — this
is a realistic amount of optimism from CV on synthetic, moderately separable
data, and is exactly the kind of signal the evaluation report and
calibration curve are there to surface. Logistic Regression's smaller gap
reflects its lower variance / higher bias as a linear model.

## Explainability

SHAP (`reports/evaluation/shap_summary.png`) and native feature-importance
(`reports/evaluation/feature_importance.png`) are generated for every
evaluation run. In practice, `previous_admissions`, `disease_burden_score`,
`hospital_utilization_score`, `hba1c`, and `follow_up_scheduled` are
consistently among the top drivers — consistent with how the synthetic
target was constructed, which is a useful sanity check that the model is
learning the intended structure rather than spurious noise.

## Limitations

- Trained on synthetic data with a hand-specified risk function; it will
  **not** generalize to real clinical populations, coding practices, or
  documentation patterns.
- Precision/recall on the minority (readmit) class is moderate (~0.54 / 0.45)
  — expected given class imbalance and synthetic noise; a real deployment
  would tune the decision threshold against a clinically-chosen
  cost-of-error tradeoff rather than the default 0.5 cutoff used here.
- No fairness/subgroup audit has been performed (e.g. by gender or
  insurance type) — this would be a required step before any real-world
  adjacent use, even research use.

## Retraining

Retraining is triggered automatically (via `/retrain` or
`src/retraining/retrain_trigger.py`) when Evidently-measured data drift
exceeds `monitoring.drift_threshold` (default 0.3 share of drifted columns)
or when live ROC AUC degrades more than
`monitoring.performance_degradation_threshold` (default 0.05) below the
metadata-recorded training-time value.
