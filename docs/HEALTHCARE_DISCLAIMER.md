# Healthcare Disclaimer

**This project is for educational and portfolio purposes only.**

## No Real Patient Data

Every record in this dataset is synthetically generated by
`src/data_generation/generate_data.py` using randomized distributions with
engineered statistical relationships. **No real patient records, protected
health information (PHI), or data derived from any real healthcare system
were used at any point in this project.**

## Not a Medical Device

This system, its model, its API, and its predictions:

- Have **not** been validated by any clinical trial.
- Have **not** been reviewed or approved by the FDA, EMA, or any other
  regulatory body.
- Are **not** compliant with HIPAA, GDPR, or any healthcare data-handling
  regulation (nor do they need to be, since no real patient data is
  processed) — deploying this against *real* patient data without a full
  compliance review would be inappropriate and potentially unlawful.
- Do **not** constitute medical advice, diagnosis, or treatment
  recommendations of any kind.

## Do Not Use for Real Clinical Decisions

**Under no circumstances should the predictions from this API be used to
make, support, or influence a real clinical decision about a real patient.**
This includes, but is not limited to: discharge planning, admission triage,
resource allocation, insurance decisions, or care-plan design.

If you are building on this project for a real-world healthcare use case,
you must, at minimum:

1. Retrain on properly consented, de-identified, IRB/ethics-board-approved
   real-world data.
2. Conduct a formal clinical validation study.
3. Engage regulatory/compliance and legal review (HIPAA/GDPR, FDA SaMD
   classification, etc., as applicable to your jurisdiction).
4. Have the system reviewed by qualified clinicians before any deployment
   near a care pathway.

## Purpose of This Project

This repository demonstrates an end-to-end, production-shaped
DevSecMLOps workflow — data generation, validation, feature engineering,
model training/tuning, experiment tracking, a served API, observability,
drift detection, and CI/CD/security tooling — using a healthcare-flavored
problem as a realistic, relatable domain. The engineering patterns are the
deliverable; the "healthcare" framing is the vehicle.
